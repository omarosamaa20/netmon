# Controller

This crate uses nftables because it is the modern packet filtering framework on Ubuntu and newer Linux systems. It also maps directly to the project requirement and is available through a stable command-line interface.

At startup, the controller ensures table and chain existence for inet filter output. This location is chosen because the project blocks outbound traffic generated by local processes, so the output hook is the right point to drop packets before they leave the host.

When block_process is called, the controller reads /proc/<PID>/net/tcp, tcp6, udp, and udp6 to collect source ports currently used by that process. It builds rules like tcp sport { ... } drop and udp sport { ... } drop, pipes the ruleset to nft -f -, then parses nft -a list chain output to capture inserted rule handles.

unblock_process deletes rules by handle, which is safer than rebuilding exact rule text. Handles are tracked in memory by PID and can also be rediscovered by scanning comments that include a netmon-pid marker. unblock_all flushes the output chain and is called on clean application exit.

The key limitation is that matching is port-based, not PID-based. If a blocked source port is later reused by another process, that traffic can also be dropped until the rule is removed.
